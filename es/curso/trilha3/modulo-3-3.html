MÓDULO 3.3 · Ruta 3 · Modelo, costo y orquestación

Encadenar subagentes

El maestro no solo activa subagentes: los encadena: el resultado de A alimenta a B, que alimenta a C. Este módulo enseña a diseñar, depurar y escalar pipelines secuenciales sin hacer que los agentes conversen entre sí.

⏱ ~25 min 🔗 7 temas 💡 Nivel intermedio

El maestro coordina toda la cadena. Los agentes no se comunican directamente: cada uno responde solo al maestro.

Contenido detallado

Qué es

Encadenar subagentes significa que el output de A se convierte en el input de B, que a su vez alimenta a C — y el maestro orquesta cada paso. No existe una conversación directa entre los agentes: la cadena vive por completo en el contexto del maestro.

Por qué aprender

✦ Separa las responsabilidades en etapas claras
✦ Cada agente opera en un contexto limpio y enfocado
✦ Facilita la depuración: falló en B, no en A ni en C
✦ Permite reutilizar etapas en otras cadenas

Conceptos clave

→
Input bridge

El maestro extrae el resultado de A y lo incorpora como contexto en el prompt de B.

→
Cadena determinista

A→B→C siempre en ese orden; el director no se salta etapas sin revisar el resultado anterior.

→
Punto de control

Entre cada etapa, el maestro puede validar, transformar o abortar antes de continuar.

Qué es

Skills son instrucciones cargadas en el contexto del maestro; ellas guían el comportamiento. Agents son subprocesos con su propia ventana; ellos ejecutan trabajo aislado. En una cadena, la skill define el flujo; los agents realizan las etapas.

Conceptos clave

✓ Skill: sirve para

  • ✓ Definir las etapas de la cadena
  • ✓ Reutilizar la lógica entre proyectos
  • ✓ Activar varios subagentes
  • ✓ Mantén corto el contexto del maestro

◎ Agent: bueno para

  • ◎ Lectura intensiva de archivos
  • ◎ Investigación web en profundidad
  • ◎ Generación de un artefacto aislado
  • ◎ Tarea con herramientas propias

💡 Consejo práctico

Usa la skill como el maestro de la cadena — contiene el prompt que inicia cada agent en secuencia e indica al maestro que haga el traspaso de outputs entre ellos.

Por qué aprender

Confundir skill con agent es el error más común al diseñar cadenas. Entender la distinción evita sobrecargar el contexto del maestro con trabajo que debería estar en una ventana separada.

Qué es

En Claude Code, un subagente no tiene permiso para lanzar otro subagente directamente. Toda delegación pasa por el maestro. Esto no es una limitación: es un diseño intencional para garantizar la trazabilidad, el control de costos y la visibilidad del flujo.

⛔ Patrón prohibido

# ❌ NêO funciona assim
Agent A → lança Agent B internamente
Agent B → lança Agent C internamente

# ✓ Como funciona de fato
Maestro → Agent A → retorna resultado
Maestro → Agent B (com output de A) → retorna resultado
Maestro → Agent C (com output de B) → retorna resultado

Por qué aprender

✗ Riesgo de ignorarlo

  • • Ciclos infinitos de delegación
  • • Costos de API sin límite
  • • Trazabilidad nula
  • • Difícil de depurar

✓ Beneficio del modelo

  • • El maestro ve todo
  • • Costo predecible por etapa
  • • Puede abortarse en cualquier punto
  • • Registros claros por agente

Conceptos clave

La arquitectura es estrella (maestro en el centro), no malla (todos conectados). Cada subagente es una hoja del árbol — nunca un nodo intermedio con hijos propios.

Qué es

Cada subagente tiene exactamente una relación: con el maestro que lo creó. No conoce a otros subagentes, no tiene acceso a su contexto y no puede influir en ellos. Es un especialista contratado para una única misión: entrega el informe y termina.

Conceptos clave: ciclo de vida

Maestro arma el prompt

Incluye el contexto necesario + la salida de la etapa anterior

El subagente abre una ventana propia

Contexto vacío: solo ve lo que envió el maestro

Ejecuta la tarea

Puede usar herramientas, leer archivos y llamar APIs

Devuelve el resultado al maestro

Texto limpio — informe único, sin conversación

La ventana se cierra: se libera el contexto

No existe un "después" para el subagente

Por qué aprender

Entender la relación 1 a 1 evita intentar "hacer que los agentes colaboren directamente", lo que falla silenciosamente, sin un error explícito.

Qué es

La decisión de secuenciar es del maestro, no de los agentes. El maestro evalúa: «¿B depende del output de A?» Si es así, es una cadena. Si no, puede ser en paralelo. Esta decisión determina la latencia vs. el costo.

Conceptos clave

🔗 Encadena cuando:

  • → B usa el resultado de A
  • → El orden importa para la calidad
  • → Precisión > velocidad
  • → Revisión incremental del resultado

⚡ Paraleliza cuando:

  • → Las tareas son independientes
  • → Velocidad > precisión
  • → Fan-out para recopilar datos
  • → N versiones para comparar después

💡 Regla general

Si puedes describir la tarea como "investiga y después redacta y después revise", es una cadena. Si es "investigue y al mismo tiempo recopilar ejemplos", es paralelo.

Por qué aprender

Encadenar cuando podrías paralelizar desperdicia latencia. Paralelizar cuando hay dependencias produce resultados incorrectos. Saber distinguirlo es la habilidad central de la orquestación.

Qué es

Una skill puede contener instrucciones que guían al maestro para lanzar subagentes en secuencia. La skill no ejecuta nada: se carga en el contexto del maestro y guía cada llamada a Agent tool.

Conceptos clave

1
La skill define el guion

Enumera las etapas, lo que recibe cada agente y lo que debe devolver.

2
Maestro ejecuta el guion

Lanza el Agent A, captura el output, prepara el prompt para el Agent B, y así sucesivamente.

3
La skill es reutilizable

El mismo flujo puede invocarse en cualquier proyecto sin reescribirlo.

Por qué aprender

Poner la lógica de la cadena en una skill hace que el proyecto sea auditable, versionable y portable. Sin este patrón, la orquestación queda dispersa en prompts ad hoc imposibles de mantener.

Qué es

Una cadena de 3-5 agentes funciona bien con un maestro humano. Por encima de eso, los outputs acumulados inflan el contexto y aumentan el costo de cada etapa. El siguiente paso natural es migrar a un workflow: herramientas como n8n, LangGraph o scripts de Python que coordinan las llamadas a agentes fuera del contexto del LLM.

Conceptos clave: señales de que es hora de escalar

⚠ Señales de alerta

  • ! Cadena con >6 etapas
  • ! El output de A apenas cabe en el prompt de B
  • ! Necesita reintentos por etapa
  • ! Costo total imprevisible

✓ Solución: workflow

  • → n8n coordina mediante JSON/HTTP
  • → El estado persiste entre etapas
  • → Reintento sin volver a ejecutar todo
  • → Logs por nodo, no por token

Por qué aprender

Saber cuándo parar de usar el maestro conversacional y migrar a un workflow es la diferencia entre un pipeline que funciona en producción y uno que colapsa en la tercera semana.

Ejemplo real

Skill que orquesta subagentes en cadena: investigación → borrador → revisión

.claude/skills/pipeline-pesquisa.md 
# pipeline-pesquisa

Orquestra 3 subagentes em cadeia para produzir um artigo pesquisado e revisado.

## Quando usar
Quando o usuário pedir "pesquise X e escreva um artigo" com qualidade alta.

## Etapas

### ETAPA 1 — Pesquisa (web-research-assistant)
Lançar um subagente `web-research-assistant` com o prompt:

```
Pesquise profundamente sobre: {TEMA}
Retorne:
- 5 fatos verificados com fonte
- 3 perspectivas contraditórias
- 1 dado quantitativo recente
Formato: markdown estruturado, máx. 400 palavras.
```

Capture o output como `PESQUISA`.

### ETAPA 2 — Rascunho (general-purpose)
Com `PESQUISA` em mêos, lançar `general-purpose`:

```
Com base nas pesquisas abaixo, escreva um artigo de 600 palavras sobre {TEMA}.
Tom: educativo, direto, sem jargêo.
Use os fatos como base; cite as perspectivas contraditórias.

--- PESQUISA ---
{PESQUISA}
```

Capture como `RASCUNHO`.

### ETAPA 3 — Revisêo (general-purpose)
Lançar `general-purpose` com o rascunho:

```
Revise o artigo abaixo para:
1. Precisêo factual (corrija erros vs. pesquisa fornecida)
2. Clareza e fluidez
3. Tamanho: mantenha 500-650 palavras
Retorne APENAS o artigo final, sem comentários.

--- RASCUNHO ---
{RASCUNHO}
--- PESQUISA ORIGINAL ---
{PESQUISA}
```

## Output
Retorne ao usuário o artigo revisado com o cabeçalho:
`## Artigo: {TEMA} (pesquisado + revisado)`

## Regras
- Maestro NêO encurta as etapas
- Se ETAPA 1 falhar, abortar com mensagem clara
- Agentes nêo se comunicam diretamente

Etapa 1

web-research-assistant recopila hechos con fuentes

Etapa 2

general-purpose transforma la investigación en un borrador

Etapa 3

general-purpose revisa y entrega el artículo final

Ejercicio

Diseña una cadena de 3 etapas para un problema real tuyo

Tarea

  1. 1. Elige un problema real de tu trabajo que implique 3 etapas distintas (p. ej., recopilar datos → analizar → redactar un informe).
  2. 2. Para cada etapa, define: nombre del subagente, input (lo que recibe del maestro) y output (quien lo devuelve).
  3. 3. Escribe el "punto de control" del maestro entre cada etapa: ¿qué valida antes de avanzar?
  4. 4. Justifica: ¿por qué cada etapa debe ser secuencial y no paralela?

Criterio de verificación

✓ Cadena bien modelada

  • ✓ Cada agente recibe solo lo necesario
  • ✓ Ningún agente llama a otro directamente
  • ✓ Maestro tiene un punto de control explícito
  • ✓ Justificación de una secuencia clara

✗ Señales de problemas

  • ✗ "Agente A le pregunta al Agente B"
  • ✗ El input de B no usa el output de A
  • ✗ Maestro no valida entre etapas
  • ✗ Las etapas podrían ejecutarse en paralelo

💡 Consejo de autoevaluación

Pon a prueba tu modelo con el "¿y si A falla?": si el director puede detectarlo y abortar antes de iniciar B, la cadena está bien diseñada. Si no, falta un punto de control.
